1. Introduction

The rapid expansion of urban areas in Somaliland has created a pressing need for modern digital solutions in the real estate sector.

Current operational practices remain manual and fragmented:

  • Informal communication channels (WhatsApp, phone calls)
  • Paper-based records and filing
  • Unstructured digital tools (social media, messaging apps)

The Solution

Guryo Samo — meaning “Your Home” in Somali — connects property seekers with available listings in a transparent, organized digital environment.

  • Public-facing property portal with advanced search
  • Secured, role-based administrative control panel
  • 100% open-source: PHP, MySQL, HTML5, CSS3, JS

2. Problem Statement

Despite significant growth in Somaliland’s real estate sector, agencies lack effective digital tools for management and client communication.

  • Inefficient Operations: Manual methods are difficult to scale and prone to information loss.
  • Fragmented Search Experience: Seekers have no centralized, localized platform to find relevant listings.
  • Cost-Prohibitive Alternatives: Commercial platforms like Zillow and Bayut are not localized for Somaliland and carry high recurring subscription costs.
  • No Analytics: Agencies cannot generate meaningful reports from scattered, paper-based records.
Core Goal: Provide a locally developed, cost-effective digital environment for property managers and prospective clients — deployable on any standard web hosting.

3. Project Objectives

3.1 General Objective

To design and develop a fully functional, web-based Real Estate Management System enabling local businesses to manage property listings, communicate with clients, and provide the public an accessible digital property portal.

3.2 Specific Objectives

  • Design a normalized relational database schema.
  • Develop a public-facing portal with advanced filtering.
  • Build a secure, role-based administrative dashboard.
  • Implement bcrypt authentication & session management.
  • Integrate a contact & messaging module.
  • Enforce SQLi, XSS, and CSRF defenses throughout.
  • Deliver an analytics and reporting module.

4. Scope and Limitations

4.1 Scope

  • Public Portal: Property listings, search/filter, property detail pages, user registration & unified login.
  • Admin Panel: Dashboard stats, full CRUD for properties, message management, user control, analytics & site settings.
  • Security Layer: Prepared statements, output escaping, CSRF tokens, MIME upload validation, bcrypt passwords.

4.2 Limitations

  • No dedicated customer-facing dashboard or saved searches.
  • Only one primary image upload per property listing.
  • No login rate limiting or brute-force lockout.
  • Database credentials stored in config/db.php (not env vars).
  • No property-specific inquiry form.
  • No advanced sorting on the listings page.

5.1 & 5.2 — Functional & Non-Functional Requirements

5.1 Functional Requirements (Key)

  • Public browsing of listings without authentication (FR-01).
  • Filter by location, type, status & max price (FR-02).
  • Paginated results with configurable page size (FR-03).
  • Role-based redirection upon login (FR-08).
  • Admin CRUD for property listings with image upload (FR-10 to FR-12).
  • Analytics & reporting dashboard (FR-15).

5.2 Non-Functional Requirements

  • Security: Prepared statements, HTML escaping, CSRF tokens, bcrypt hashing, MIME validation.
  • Usability: Responsive design, informative form feedback.
  • Performance: SQL LIMIT/OFFSET pagination.
  • Reliability: Graceful error handling for invalid IDs.
  • Compatibility: PHP 7.4+, MySQL 5.7+.

6. Project Feasibility

6.1 Technical & 6.2 Economic

  • Technical — High: SSR architecture eliminates complex state management. Standard LAMP/XAMPP stack, well-documented and widely supported.
  • Economic — High: 100% open-source, zero licensing cost. Deployable on shared hosting for ~$3–$10/month with no per-listing fees.

6.3 Operational & 6.4 Schedule

  • Operational — High: Follows standard CMS and property portal UI patterns. Near-zero learning curve for both admins and public users.
  • Schedule — Achieved: Built using Agile incremental methodology. All 6 phases completed within an 8–12 week academic semester.

7. Methodology

Developed using an incremental and iterative Agile approach, allowing continuous refinement and early detection of design issues.

  • Phase 1: Requirements Elicitation & Analysis — user roles, database schema, functional decomposition.
  • Phase 2: Database Design — relational model, SQL schema, seed data.
  • Phase 3: Backend Architecture — config/db.php, includes/functions.php, shared utilities.
  • Phase 4: Frontend & Backend Page Development — public and admin pages built concurrently.
  • Phase 5: Security Integration — CSRF, SQLi, XSS, MIME validation applied throughout.
  • Phase 6: Testing & Debugging — manual happy-path and edge-case testing across all modules.
  • Phase 7: Documentation — comprehensive project guide, README, and academic defense material.

8. Results and Outcomes

All seven specific objectives were fully met. The system is functional, demonstrable, and ready for local deployment.

Delivered Modules

  • ✓ Responsive Public Portal & Dynamic Search
  • ✓ Role-Based Admin Dashboard
  • ✓ Property CRUD with Image Uploads
  • ✓ User & Message Management
  • ✓ Analytics & Site Settings Panel

Security Outcomes

  • SQL Injection → Parameterized queries
  • XSS → htmlspecialchars() output escaping
  • CSRF → Cryptographic token on every POST
  • Session Fixation → session_regenerate_id()
  • Password Exposure → bcrypt hashing only

9. Conclusion & Recommendation

Conclusion

Guryo Samo successfully bridges the digital gap in Somaliland’s real estate sector. It delivers a centralized, secure, and cost-effective platform covering the full project lifecycle — from requirements and design to implementation, testing, and documentation.

The project demonstrates competency in full-stack web development, relational database design, and practical web application security.

Recommendations

  • Implement login rate limiting before production.
  • Migrate credentials to environment variables (.env).
  • Enforce HTTPS via Apache .htaccess redirect.
  • Build a customer dashboard with saved favorites.
  • Add multi-image galleries per property listing.
  • Consider adopting a lightweight MVC framework (Laravel/Slim) for long-term scalability.
